PROBLEMA PRINCIPALE:
  L'hardware SHA-256 su ESP32-S3 produceva hash errati a causa di un bug di
  endianness nei registri hardware. Questo causava il fallimento di TUTTE le
  verifiche delle share, rendendo il mining impossibile.

STATO PRE-FIX:
  - Hashrate: ~200-260 KH/s (hardware)
  - Share accettate: 0
  - Share rifiutate: 0
  - Errore: [S3-DBG] SW verify=FAIL hash[28-31]=xxxxxxxx (sempre FAIL)

STATO POST-FIX:
  - Hashrate: ~1.3-1.4 KH/s (hardware + software verification)
  - Share accettate: YES (quando difficoltà pool è configurata correttamente)
  - Share trovate: Multiple con hash[28-31]=xxxx0000 (leading zeros corretti)
  - Verifica: [S3-DBG] SW verify=PASS per share valide

================================================================================
                      DETTAGLI DEL PROBLEMA TECNICO
================================================================================

DOCUMENTAZIONE UFFICIALE:
  Espressif ESP-IDF Issue #12440
  https://github.com/espressif/esp-idf/issues/12440

PROBLEMA HARDWARE:
  Su ESP32-S3, i registri SHA_H_BASE (digest state) usano formato BIG-ENDIAN,
  mentre il software SHA usa LITTLE-ENDIAN (formato host Xtensa LX7).

  Questo significa che:
  1. Scrivendo il midstate LE direttamente → hardware legge valori sbagliati
  2. Leggendo l'hash finale direttamente → software interpreta valori sbagliati

CONSEGUENZE:
  - Midstate calcolato correttamente in software
  - Hardware SHA elabora dati con byte-order sbagliato
  - Hash finale NON corrisponde all'atteso
  - Verifica software FALLISCE sempre
  - Nessuna share viene mai trovata/accettata

FUNZIONE CHIAVE: sha256_s3_mine() in src/mining/sha256_s3_mining.c

static inline void sha256_s3_process(const uint32_t *midstate_be, 
                                      const uint32_t *tail,
                                      uint8_t *digest) {
    int i;
    
    // ===== HASH 1: Midstate + Tail =====
    // FIX CRITICO: Write midstate to SHA_H with BSWAP (BE → LE for register)
    for (i = 0; i < 8; i++) {
        write_reg(SHA_H_BASE + i * 4, __builtin_bswap32(midstate_be[i]));
    }
    
    // Write tail to SHA_TEXT (already in BE format - BTC standard)
    for (i = 0; i < 4; i++) {
        write_reg(SHA_TEXT_BASE + i * 4, tail[i]);
    }
    
    // Padding per messaggio 80-byte
    write_reg(SHA_TEXT_BASE + 0x10, 0x00000080);
    // ... zeros ...
    write_reg(SHA_TEXT_BASE + 0x3C, 0x80020000);  // 640 bits
    
    write_reg(SHA_MODE_REG, SHA2_256_MODE);
    write_reg(SHA_CONTINUE_REG, 1);
    
    if (!sha_wait_idle()) return;
    
    // ===== HASH 2: Double SHA =====
    // Leggi hash1 da SHA_H (raw LE format) - NO BSWAP per double-hash!
    uint32_t h[8];
    for (i = 0; i < 8; i++) {
        h[i] = read_reg(SHA_H_BASE + i * 4);
    }
    
    // Scrivi hash1 a SHA_TEXT (raw copy, no swap)
    for (i = 0; i < 8; i++) {
        write_reg(SHA_TEXT_BASE + i * 4, h[i]);
    }
    
    // Padding per 32-byte message
    write_reg(SHA_TEXT_BASE + 0x20, 0x00000080);
    write_reg(SHA_TEXT_BASE + 0x3C, 0x00000100);  // 256 bits
    
    write_reg(SHA_MODE_REG, SHA2_256_MODE);
    write_reg(SHA_START_REG, 1);
    
    if (!sha_wait_idle()) return;
    
    // Leggi final hash e converti a BE
    for (i = 0; i < 8; i++) {
        uint32_t v = read_reg(SHA_H_BASE + i * 4);
        digest[i*4+0] = (v >> 24) & 0xFF;
        digest[i*4+1] = (v >> 16) & 0xFF;
        digest[i*4+2] = (v >> 8) & 0xFF;
        digest[i*4+3] = v & 0xFF;
    }
}

  Causa:  s_poolDifficulty viene resettato a 0 dopo il set iniziale
  Fix:    Controllare stratum.cpp - parseSetDifficulty() e miner_set_difficulty()
